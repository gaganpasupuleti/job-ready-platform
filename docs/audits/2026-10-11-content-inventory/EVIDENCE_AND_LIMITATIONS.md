## How the evidence was produced

The inventory reads only the pinned commits above through `git show` and
`git ls-tree`. It never reads the working tree, never imports or runs seed modules
(it parses their syntax), and never opens a database connection. If a pinned commit
or file is missing, it stops with `SourceUnavailable` instead of substituting another
branch.

Regenerate from `backend/`:

```
python -m app.content.inventory --out ../docs/audits/2026-10-11-content-inventory
```

Check committed files without rewriting them:

```
python -m app.content.inventory --out ../docs/audits/2026-10-11-content-inventory --check
```

Item IDs such as `master/phase11-aptitude/#067` are source locators, not database IDs.
Stem fingerprints use `app.content.hashing.content_hash`, the same normalized hash the
Phase 11 activation uses for duplicate detection.

## Limitations

- Actual published database rows: Production verification pending.
- Coding problem execution: Production verification pending. Judge0 activation is out of scope.
- The canonical Astra 42-topic list is not in the repository. The coverage matrix
  uses repository topics (40) and needs human confirmation.
- "Reviewed" means the agent quality gate on Sprint 1. No human content approval is
  recorded for PR #18 or for the 17 version 2 revisions.
- Batch questions from the 2026-09-14 and 2026-09-19 batches carry skills, not topics.
  The importer files every batch question under one `studio-saturday-001` topic, so
  database topic counts will not match this matrix.
- Learning path availability declared in source can change at seed time:
  `build51_seed` marks existing DSA paths as available. See `README.md` for the local
  seed check.
- Semantic duplicate detection is lexical. It cannot find paraphrases with different
  words, and it flags some distinct questions.
- Generated interview files under `backend/content/generated/` are listed as drafts.
  No importer reference was verified.
